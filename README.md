# Диспетчер скриптов 1.2.17

Единая Windows-программа для запуска, настройки и планирования рабочих скриптов. Интерфейс выполнен в виде табличного диспетчера: задача, модуль, рабочая папка, расписание, состояние, последний и следующий запуск.


## Изменение v1.2.17: ежедневный сброс статуса

- Для заданий **с расписанием** успешный запуск сегодня показывает «Готово» до конца дня.
- С наступлением следующего календарного дня (в часовом поясе планировщика) статус становится «Ожидание» до первого запуска в новом дне.
- Смена статуса проверяется каждые 10 секунд даже без перезапуска программы; история сохраняется в SQLite, поэтому логика работает и после перезапуска.
- «Выполняется», «Останавливается», «Отключено», ошибки и ручные задачи обрабатываются отдельно. Если сегодня завершилось ошибкой, будет «Ошибка»; в следующий день — «Ожидание».
- При нескольких запусках в течение одного дня «Готово» означает, что задание уже успешно выполнялось сегодня, **а не** что все запланированные на день запуски завершены. Следующие запуски произойдут по обычному расписанию.
- Логика повторной вырезки и расписание не изменены.

## GitHub + Codex

1. Создайте **Private** репозиторий `ScriptDispatcher` на GitHub (пустой, без автоматических README или `.gitignore`).
2. Добавьте в репозиторий **содержимое этой папки**, не исходный архив v1.2.16 с секретами. Инструкция: `GITHUB_SETUP.md`.
3. Откройте Codex и подключите репозиторий. Рекомендации для агента в `AGENTS.md`.
4. Workflow `Tests` проверяет изменения, а `Windows EXE Build` по ручному запуску собирает Windows EXE и прикладывает артефакт.
5. Для обновления установленной программы резервируйте **всю** папку `data`; при CI-сборке она намеренно отсутствует. После загрузки сборки положите свою папку `data` в `ScriptDispatcher` рядом с EXE.

## Дополнения 1.2.16 — универсальная вырезка

**Имя выходного MP3:** в настройке источника (`Универсальная вырезка` → `Источники` → `Изменить` → `Название / шаблон MP3 в cash`) можно использовать:

| Шаблон | Для записи 25-08-2026 11:00 |
| --- | --- |
| `{dd-mm-yy}` | `25-08-26` |
| `{dd-mm}` | `25-08` |
| `{hour-minute}` | `11-00` |
| `{hour+1-minute}` | `12-00` |
| `{hour+1-minute+30}` | `12-30` |

Пример: `Новости столица {dd-mm-yy} {hour+1-minute+30}` → `Новости столица 25-08-26 12-30.mp3`. Сдвиг времени меняет дату при переходе через полночь, например 31-12-2026 23:45 + 1:30 = 01-01-27 01:15. Ранее поддержанные `{date}` и `{date-full}` работают по-прежнему.

**Защита от повторов:** при редактировании задания в параметрах модуля появилась независимая галочка **«Не вырезать повторно уже обработанные часы (сохранять историю)»**. Если она включена, каждый успешно обработанный выпуск по конкретному источнику, дате и часу отмечается отдельным файлом в `data/universal_cut_history`. После этого повторные запуски не будут снова вырезать и загружать уже обработанный выпуск. Успех означает, что запись вырезана и отправлена во все включённые архивы; если отправка не завершена, повторная попытка разрешена.

История сохраняется отдельно от временной папки `cash`, но её **необходимо переносить вместе со всей папкой `data`** при пересборке EXE или переезде программы. Старые выпуски, обработанные *до включения* галочки, в историю автоматически не заносятся. Для принудительной повторной вырезки временно снимите эту галочку. При смене шаблона имени или CUE-маркеров история для новой конфигурации создаётся отдельно.

## Дополнения последней сборки (архивы и имена файлов)

В модуле **«Универсальная вырезка»** появились две независимые галочки:

- **Отправлять в архив радио** — `extracted_media` (включена по умолчанию для совместимости со старыми заданиями).
- **Отправлять в архив республика** — `archive_respublika` (по умолчанию выключена).

Можно включить обе, одну или ни одной. При отключённой отправке файлы всё равно создаются локально.

Для каждого источника в поле **«Название / шаблон MP3 в cash»** можно указать, например:

`Новости столица {date} {hour-minute}`

При времени вырезки 12 августа 2026 года, 18:00 результат будет:

`Новости столица 12-08-26 18-00.mp3`

Переменные: `{date}` (ДД-ММ-ГГ), `{date-full}` (ДД-ММ-ГГГГ), `{hour-minute}` (ЧЧ-ММ), `{hour}`, `{minute}`, `{second}`, `{source}`. Существующие обычные имена без скобок работают по-прежнему. При включённой отправке MP3 с новым названием уходит в выбранные архивы.

## Как обновить и сохранить задания планировщика

**Не удаляйте папку `data` установленного приложения.** В ней хранятся `config.json` (задания и расписания), `secrets.dat` (закрытые настройки) и `history.sqlite3` (история). Сохраните копию всей папки `data` перед заменой собранного приложения.

В ZIP находятся **исходники Python, не готовый EXE**. Для запуска в Python используйте `install_and_run.bat` либо `run.bat`; чтобы получить EXE, запускайте `build_exe.bat`. Если вы уже собирали EXE в `dist\ScriptDispatcher`, можно вместо обычной сборки использовать `СОБРАТЬ_С_СОХРАНЕНИЕМ_НАСТРОЕК.bat`: он делает резервную копию папки `dist\ScriptDispatcher\data`, собирает приложение и восстанавливает данные. Если рабочий EXE установлен в другой папке, скопируйте `data` из неё вручную или сохраните перед обновлением.

**Безопасность GitHub:** прежние секреты из исходного ZIP удалены. `dispatcher/private_defaults.py` содержит только пустые/публичные значения, а `private/yandex_cookie.txt` не включён. Укажите ключ и Cookie через «Настройки» в программе. Не размещайте папку `data` в репозитории.

## Быстрый запуск

1. Распакуйте папку программы, например в `D:\ScriptDispatcher`.
2. Установите 64-битный Python 3.11 или 3.12 с сайта python.org.
3. Запустите `install_and_run.bat`.
4. При первом старте установка библиотек может занять несколько минут.
5. Для следующих запусков используйте `run.bat`.

Все созданные задачи первоначально отключены и запускаются только вручную. Автоматический запуск нужно отдельно разрешить в настройках конкретной задачи.

## Первый запуск

Откройте **Настройки** и проверьте:

- часовой пояс, обычно `Europe/Moscow`;
- путь к `ffmpeg.exe`, если FFmpeg не добавлен в системный PATH;
- путь и профиль браузера;
- адрес сервера внутреннего сетевого бота;
- внутренний ключ, канал и заголовок;
- Cookie Яндекс Музыки, если используется «Карточка музыканта».

Ключ внутреннего бота и Cookie указываются пользователем через «Настройки». На Windows они сохраняются в локальном DPAPI-контейнере текущего пользователя и не входят в репозиторий.

## Встроенные модули

### Эфир

- Новости, «Тормозок» и интервью для Кометы, Столицы и Бриза.
- «Утренняя смена».
- «Универсальная вырезка»: несколько папок в одном задании, отдельные часы, сообщения и имена файлов для каждого источника; два режима — «влёт → вылет» и «один маркер = один непрерывный блок подряд идущих CUE-треков». В режиме одного маркера все соседние треки, содержащие заданный текст (например `Новости`), объединяются в один выпуск до первого трека без этого текста.
- «Утренний гость».
- Локальная вырезка новостей из выбранной папки.

Можно менять сетевые пути, IP-адреса, часы записей, маркеры CUE, режим даты, папку результата, отправку во внутренний бот и очистку созданных файлов. Для ручной даты используется календарь и отдельный набор часов Кометы, Столицы и Бриза. Режимы «Сегодня» и «Последний рабочий день» используют свой общий набор часов; значения двух профилей не перезаписывают друг друга. Если папка результата не указана, используется `cash` рядом с программой, как в исходных скриптах.

Эфирные файлы отправляются только во внутренний сетевой бот:

- текстовые разделители — `POST /api/internal/message`;
- MP3-файлы — `POST /api/internal/upload`;
- канал по умолчанию — `extracted_media`;
- заголовок по умолчанию — `Вырезки из эфира`;
- для новостей Кометы, Столицы и Бриза сообщение и название файла настраиваются независимо;
- отдельно настраиваются также «Тормозок» и интервью;
- их названия можно менять кнопкой «Редактировать название»: подписи маркеров, сообщения и имени файла подхватывают новое название;
- в полях названия файла новостей используются обычные значения `kometa`, `stolica`, `briz` и т. п., без технических шаблонов;
- дата, время исходной записи и `.mp3` сохраняются автоматически: например `stolica` превращается в `stolica_17-08-2026_11-00.mp3`;
- текст сообщения можно менять отдельно для каждой станции; в нём поддерживается `{date}`, а для интервью также `{hour}`.

### Музыка

- Перенос BPM из ID3 в APEv2.
- Карточка музыканта по данным Яндекс Музыки.
- Проверка названий MP3 по блок-листу.
- Распределение РУС/АНГЛ.
- Составление списка MP3.
- Поиск и загрузка композиций по списку.

Перед изменением музыкальных тегов по умолчанию создаются резервные копии в папке конкретного запуска.

### Яндекс

- Создание поисковых ссылок из TXT.
- Последовательное открытие ссылок в выбранном браузере и профиле.

### Excel

Один модуль заменяет два исходных скрипта:

- **Полная очистка** — объединение листов, удаление строк с `не указано`, неполных строк и дублей, форматирование времени, подсчёт итога.
- **Только время и итог** — сохраняет структуру книги и ничего не удаляет.

Если выходной файл не указан, результат с суффиксом `_готово.xlsx` сохраняется рядом с выбранным исходным Excel-файлом.

### Внешний запуск

Можно добавить любой `.py`, `.bat`, `.cmd` или `.exe`, задать:

- рабочую папку;
- аргументы;
- путь к Python;
- тайм-аут;
- собственное расписание.

## Планировщик

Поддерживаются:

- выбранные дни недели;
- несколько точных времён в день;
- повтор через заданный интервал;
- временное окно, например с 08:00 до 19:00;
- выполнение пропущенного запуска после старта программы;
- ручной запуск;
- остановка выполняющейся задачи, включая зависшую обработку или сетевую отправку.

Для работы расписания программа должна быть запущена. Закрытие окна по умолчанию сворачивает её в область уведомлений.

Разные задачи не запускаются одновременно, если используют одну и ту же входную или выходную папку.

## Где хранятся данные

В подпапке `data` рядом с программой:

- `config.json` — настройки и задачи;
- `secrets.dat` — защищённые ключ внутреннего бота и Cookie;
- `history.sqlite3` — история запусков;
- `logs` — подробные журналы;
- `temp` — отдельные рабочие папки запусков и резервные копии.

## Сборка EXE

После успешного запуска исходной версии выполните `build_exe.bat`.

Готовая сборка появится в:

`dist\ScriptDispatcher\ScriptDispatcher.exe`

Используется формат `onedir`: EXE и его служебные библиотеки находятся в одной папке. Так программа запускается быстрее и стабильнее, чем один большой самораспаковывающийся файл.

## Важные замечания

- Программа никогда не удаляет исходные MP3/CUE после отправки.
- FFmpeg и другие консольные подпроцессы на Windows запускаются скрыто, без всплывающих окон.
- После успешной отправки эфирная папка `cash` очищается так же, как в исходных скриптах.
- При нажатии **Стоп** необработанные файлы не удаляются.
- Сетевые папки можно проверить кнопкой **Проверить доступ**.
- Журналы ошибок сохраняются даже после закрытия программы.
- Если внешний сайт изменит разметку, модуль скачивания по списку может потребовать обновления.
